# 性能日志说明

为了方便连续跑几轮后定位真正的耗时点，项目现在额外写一份独立的性能日志，不再把每次模板匹配、OCR、截图都刷进 `debugLog.log`。

## 文件位置

```text
logs/perfLog.log
```

- 每行一个 JSON；
- 10MB 轮转，保留 5 份；
- 文件本身在 `.gitignore` 的 `logs` 目录下，不提交到 git；
- 提交的是日志代码、分析脚本和本文档。

## 开关

默认开启。需要临时关闭时：

```powershell
$env:AALC_PERF_LOG = "0"
```

自定义路径（一般不需要）：

```powershell
$env:AALC_PERF_LOG_PATH = "D:\temp\perfLog.log"
```

## 主要事件

| event | 含义 |
| --- | --- |
| `run_start` / `run_end` | 一轮进程的开始/结束，包含分辨率、截图间隔、粗搜参数 |
| `task_start` / `task_end` | 任务开始/结束和耗时 |
| `screenshot` | 截图等待、截图耗时、距上一帧时间 |
| `match` | 单目标模板匹配 |
| `multi_match` | 多目标模板匹配 |
| `ocr` | 一次 OCR 裁剪/缓存结果 |
| `ocr_engine` | OCR 引擎内部耗时（缩放、预处理、推理） |
| `ocr_match` | OCR 文本命中 |
| `retry` / `retry_heavy` / `retry_handled` / `retry_end` | 重试弹窗检查 |
| `sleep` | 200ms 以上的固定等待 |
| `action` | 鼠标/键盘输入 |
| `theme_pack` | 主题包选择结果、耗时、拖拽点 |
| `vision_summary` | 每层/每轮结束的模板和 OCR 汇总 |

## 分析

```powershell
.\.venv\Scripts\python.exe scripts\analyze_perf_log.py logs\perfLog.log
```

如果日志已经轮转：

```powershell
.\.venv\Scripts\python.exe scripts\analyze_perf_log.py logs\perfLog.log logs\perfLog.log.1 --top 30
```

脚本会输出：

- 任务耗时表；
- 截图调用点和总耗时；
- 模板匹配/多目标匹配的 Top 目标；
- OCR 调用数、缓存命中、Top 区域和文本；
- sleep/action 的 Top 调用点；
- 帧间隔中“未被截图/匹配/OCR/sleep/action 解释”的时间；
- 主题包选择记录。

## 使用建议

1. 跑 2–3 轮镜牢（或镜牢 + 日常）；
2. 保留 `logs/perfLog.log` 及 `perfLog.log.1`；
3. 把文件留在本地或打包发给维护者；
4. 分析脚本只依赖标准库，可在另一台机器上直接运行。
