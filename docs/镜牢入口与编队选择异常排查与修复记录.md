# 镜牢入口与编队选择异常排查与修复记录

## 1. 故障背景与现象

在今日进行自动化优化后，用户反馈：
> **“在镜牢入口还没确认就说进入编队选择了”**

从用户交互视角观察：
游戏画面停留在镜牢入口大厅（探索模式选择或主面板），尚未进入实际战斗流程，但脚本日志和控制台提示已进入“编队选择”，并随后频繁出现：
```log
[DEBUG] tasks\mirror\mirror.py:1551: 选择队伍识别次数剩余25次
[DEBUG] tasks\mirror\mirror.py:1551: 选择队伍识别次数剩余20次
...
[DEBUG] tasks\mirror\mirror.py:1551: 选择队伍识别次数剩余0次
[ERROR] 无法进入镜牢,尝试回到初始界面
```
最终导致流程卡死在镜牢大厅并超时退出。

## 2. 日志全链路排查与根本原因剖析

依据 `logs/debugLog.log` 完整追踪（11:28:55 ~ 11:29:35），实际发生的因果链条如下：

### 2.1 第一阶段：成功进入了第一层编队界面
1. **11:28:55**：脚本在镜牢大厅点击“进入”（`enter_assets.png`，坐标 `(1664, 733)`）。
2. **11:28:56**：因账号存在探索中的进度（`Exploring: Mirror of Flames and Spiders-F1`），脚本匹配并点击“恢复探索”（`resume_assets.png`，坐标 `(950, 588)`，相似度 `0.984`）。
3. **11:28:59**：游戏正常恢复到了第一层的罪人编队界面，成功识别到了编队特征：
   - 匹配到 `mirror/road_to_mir/select_team_stars_assets.png`（相似度 `0.990`，坐标 `(1725, 807)`）
   - 匹配到 `teams/identify_assets.png`（相似度 `0.989`，坐标 `(1800, 266)`）
4. 随后 `tasks/mirror/mirror.py` 调用 `select_mirror_team()`，并进入 `tasks/teams/team_formation.py::select_battle_team()`。

### 2.2 第二阶段：今日优化引发的局部坐标偏移致命 Bug
在今日提交 `5a1cff3f`（`perf(teams): 增加编队快速选择路径并精简 OCR 识别区域`）中，为了大幅降低 RapidOCR 的推理耗时，将原本全宽的 `position_bbox = (0, 0, ...)` 优化为了极窄高能效裁剪区域：
```python
team_crop_bbox = (
    max(0, position[0] - 120 * scale),
    position[1] + 30 * scale,
    position[0] + 130 * scale,
    position[1] + 580 * scale,
)
# 1080P 下实际值为 (98, 450, 285, 862)
```
1. 脚本点击 `(187, 539)` 正常展开了左侧队伍抽屉。
2. RapidOCR 在裁剪图 `(98, 450, 285, 862)` 内识别到了队伍名称：
   ```log
   OCR识别结果：('TEAMS#1', 'TEAMS#2', 'TEAMS#3', 'TEAMS#4', 'TEAMS#5', 'TEAMS#6', 'TEANS#7')
   ```
3. **关键缺陷暴露**：
   - RapidOCR 识别的是裁剪后的局部小图，返回的框坐标中心为局部相对坐标 **`[98.5, 71.0]`**。
   - `module/automation/automation.py` 中的 `_run_ocr_for_text` **没有将 `my_crop` 的起始偏移 `(98, 450)` 补偿给 OCR 坐标**！
   - 真实的屏幕全局坐标本应为：
     $$\text{ScreenX} = 98.5 + 98 = 196.5$$
     $$\text{ScreenY} = 71.0 + 450 = 521.0$$
4. **Fast-Path 判定失效**：
   - 快速路径检查 `safe_top <= team_position[1] <= safe_bottom`（即 `450 <= 71.0 <= 862` 为 `False`），误认为目标队伍在屏幕之外，快速直选被跳过。
5. **Slow-Path 发生致命误点**：
   - 回退到慢速路径后，脚本执行了 5 次正向滑动复位。
   - 慢速路径重新 OCR 依旧得到局部坐标 `[98.5, 71.0]`，且此前慢速路径**没有加安全边界校验**，直接执行：
     ```log
     [DEBUG] Scrcpy 点击位置：(98, 71)
     [INFO]  tasks\teams\team_formation.py:170: 成功找到队伍 # 2
     ```
   - **在 1080P 游戏界面中，`(98, 71)` 恰好位于屏幕最左上角的「返回键（`<`）」！**
   - 这一点击瞬间关闭了编队选择界面，**强行退回到了镜牢入口大厅**！

### 2.3 第三阶段：状态错位与大厅死循环
1. `select_battle_team()` 虽然实际退回了大厅，但函数逻辑因成功识别到目标文本而返回了 `True`。
2. 外层的 `select_mirror_team()` 误以为编队已经完成，接着进入下一阶段：等待并点选编队确认（`select_team_confirm_assets.png`）和层级确认（`level_confirm_assets.png`），以便进入星光页面。
3. 但由于画面已被那一发 `(98, 71)` 点击退回到了镜牢大厅，大厅中根本不存在编队确认按钮。
4. 脚本在 `select_mirror_team` 的 `while` 循环中持续轮询 30 次，每隔 5 次打印一次剩余次数，最终超时报错退出。
5. 用户此时肉眼看到的就是：**游戏明明在大厅，什么都没确认，但控制台却一直说自己在进行编队选择**。

## 3. 修复措施

### 3.1 底层修复：OCR 局部裁剪坐标全局化（根本修复）
在 `module/automation/automation.py` 的 `_run_ocr_for_text` 中，为所有 OCR 识别出的文本中心坐标统一叠加 `my_crop` 的起始偏移量：

```python
# module/automation/automation.py
ocr_texts = getattr(ocr_result, "txts", None)
ocr_boxes = getattr(ocr_result, "boxes", None)
ocr_text_list = list(ocr_texts) if ocr_texts is not None else []
ocr_position_list = []
crop_offset_x = float(my_crop[0]) if my_crop is not None else 0.0
crop_offset_y = float(my_crop[1]) if my_crop is not None else 0.0
for box in ocr_boxes if ocr_boxes is not None else []:
    x = (box[0][0] + box[2][0]) / 2 + crop_offset_x
    y = (box[0][1] + box[2][1]) / 2 + crop_offset_y
    ocr_position_list.append([x, y])
ocr_dict = {text: position for text, position in zip(ocr_text_list, ocr_position_list)}
```
该修复保证全工程中任何传入 `my_crop` 的 OCR 操作（`find_language_text`、`find_text_element` 等）返回的均为真实屏幕绝对坐标。

### 3.2 业务防御：Slow-Path 增加安全点击区间保护
在 `tasks/teams/team_formation.py` 的慢速兜底路径中，同步加入与 Fast-Path 严格一致的安全上下边界检查：
```python
# tasks/teams/team_formation.py
if team_position := auto.find_language_text(team_name_zh, team_name_en, my_crop=team_crop_bbox):
    if safe_top <= team_position[1] <= safe_bottom:
        auto.mouse_action_with_pos(team_position, offset=False)
        find = True
        break
```
确保无论出现任何异常坐标或半截遮挡文本，绝不盲点屏幕左上角等危险边界区域。

### 3.3 流程平滑：入口确认与恢复点击增加画面切换缓冲
在 `tasks/mirror/mirror.py` 的 `road_to_mir()` 中，对“恢复探索”（`resume_assets.png`）和“进入镜牢”（`enter_mirror_assets.png`）的点击后增加 `sleep(1)` 等待画面彻底加载切走，避免外层主循环在同帧残留画面下重复点击入口按钮。
